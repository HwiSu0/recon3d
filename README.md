# 통로 3D 복원

불투명한 상자 속 호스에 철 현탁액을 흘리고, 바깥 자기장 센서 4대의 측정값으로 호스가 지나간 길을 3차원으로 복원하고 호스 내경을 추정하는 웹 프로그램입니다.

설치할 것이 없습니다. 페이지를 열고 Capstone CSV를 넣으면 브라우저 안에서 계산하고, 돌려 볼 수 있는 3D 결과를 보여 줍니다. 측정 파일은 서버로 전송되지 않습니다.

페이지 주소: <https://hwisu0.github.io/recon3d/>

## 사용법

1. **CSV 열기**: Capstone에서 File > Export Data > Export to file로 저장한 CSV를 넣습니다. 여러 Run이 든 파일도 되고, 가장 마지막 Run이 먼저 선택됩니다.
2. **출구별 유량**: 재었으면 mL/s로 넣습니다. 안 쓴 출구는 비웁니다. 몰라도 복원은 됩니다.
3. **복원 시작**을 누릅니다. 끝나면 3D 결과가 오른쪽에 나타나고, HTML과 JSON으로 저장할 수 있습니다.

### 측정 중 충격

센서는 코일 자기장 약 1900 μT 안에 있어서 $0.03^\circ$만 돌아가도 값이 $1900\sin 0.03^\circ \approx 1$ μT 바뀝니다. 철 신호와 비슷한 크기입니다. 책상이나 상자를 건드리면 센서가 약 6 Hz로 떨리고, 멈춘 뒤에도 값이 어긋난 채로 남습니다.

프로그램은 50 Hz 원본에서 이 떨림을 찾아 그 구간을 맞춤에서 빼고, 어긋남을 없앱니다. 철이 오기 전의 충격은 앞뒤 값으로 어긋남을 재고, 철이 온 뒤의 충격은 앞머리 모델과 함께 풉니다. 복원 결과의 **충격** 줄에 찾은 구간이 나옵니다.

Run #40에 Run #58과 같은 크기의 충격을 넣어 시험했습니다. 철이 오기 전이나 신호가 평평한 때의 충격은 경로 평균 오차가 충격 없을 때(0.39 cm)와 거의 같았습니다. 앞머리가 빠르게 지나는 순간과 겹치면 구조를 잘못 고를 수 있고, 맞춘 구간 안에 충격이 있으면 경고를 표시합니다. 측정할 때는 상자와 탁자를 건드리지 않는 것이 가장 좋습니다.

측정으로 찾을 수 없는 장치 값은 저장된 설정을 씁니다. 상자 크기, 입구와 출구 구멍, 센서 위치, 코일, 호스가 내리막만 간다는 조건입니다. Run 번호에 맞는 값을 자동으로 고르고, 센서를 옮겼으면 **고급 설정**에서 고칩니다. 값을 직접 넣고 싶을 때도 고급 설정을 쓰며, 비워 두면 자동입니다.

### 구조 고르기

`topology`가 `auto`면 후보 구조를 모두 맞춰 보고 점수가 가장 낮은 것을 고릅니다. 결과의 **구조** 칸에서 후보별 점수를 비교할 수 있습니다.

점수는 베이즈 증거의 라플라스 근사입니다. 각 매개변수의 탐색 범위를 1로 놓고, 맞춘 답에서 잔차를 미분한 야코비 행렬을 $J$라고 하면 다음과 같습니다.

$$S = \frac{\chi^2}{c} + \sum_j \ln \max\left(\frac{\lambda_j}{2\pi}, 1\right), \qquad \lambda_j : \frac{J^{\mathsf T} J}{c}\text{의 고유값}$$

$$c = f \max\left(1, \frac{\chi^2_\mathrm{min}}{N}\right), \qquad f = \frac{1+\rho}{1-\rho}$$

$\rho$는 $\chi^2$이 가장 낮은 후보의 잔차에서 잰 이웃한 시간끼리의 상관이고, $N$은 자료 수입니다. 실측에는 앞머리 모델로 설명되지 않는 신호가 시간에 따라 이어져 남기 때문에 $c$로 $\chi^2$ 차이를 줄입니다.

매개변수 수를 그대로 세는 BIC와 달리, 측정이 정하지 못하는 방향은 점수를 더하지 않습니다. 앞선 두 후보의 차이가 10보다 작으면 결과에 경고를 표시합니다.

합류 관은 모든 관이 같은 호스라고 보고 맞춥니다. 두 갈래의 압력 차가 같으므로 속도는 길이에 반비례하고, 두 갈래 속도의 합이 합류 전후의 속도입니다.

$$U_1 L_1 = U_2 L_2, \qquad U_1 + U_2 = U_0$$

철 양도 모든 관에서 같습니다. 이 조건이 없으면 한 갈래에만 철을 몰아 사실상 한 줄 관이 된 답이 나옵니다. `hose_mm`에서 갈래 굵기가 다르면 이 조건을 쓰지 않으며, `loop_tie`로 직접 정할 수도 있습니다.

상자 안 속도가 29 cm/s를 넘거나 앞머리 폭이 0.12초보다 짧은 답은 앞머리가 그 관을 지나가는 모습을 맞춘 것이 아니므로 뒤로 미루고, 표에 `탐색 범위 끝`으로 표시합니다.

구조는 단순한 것부터 맞춥니다. 합류 관은 한 줄 관이 잘 맞은 출구에서만 시험합니다 (`exit_near`). 호스는 3 mm와 5 mm뿐이므로 굵기 변화 관의 굵기 비가 1.3보다 작으면 굵기 변화로 보지 않고 표에 `굵기 변화 없음`으로 표시합니다 (`step_min_ratio`). `hose_mm`의 굵기가 모두 같으면 굵기 변화 관은 후보에서 뺍니다.

| 값 | 구조 |
| --- | --- |
| `single` | 한 줄 관. 중간점 1개, 굵기 일정 |
| `step` | 중간에 굵기가 바뀌는 한 줄 관. 바뀌는 점 P와 앞뒤 속도, 철 양을 따로 찾습니다 |
| `loop` | 갈라졌다 다시 모이는 관. 분기점 J1, 합류점 J2, 갈래마다 중간점을 찾습니다 |
| `y` | 갈래마다 다른 출구로 나가는 Y자 |

`candidates`로 후보를 줄일 수 있고, `exit`가 `auto`면 출구마다 모든 후보를 맞춥니다. `try_y`는 Y자를 후보에 넣을지 정합니다. `prior`의 `straight_sigma_cm`은 곧은 관을, `downhill`은 내리막 관을 선호하게 합니다. 후보가 많을수록 오래 걸리므로 구조나 출구를 알면 직접 정하는 편이 빠릅니다. 2단계에서 가장 좋은 후보보다 $\chi^2$이 1.5배 넘게 큰 후보는 마무리를 건너뛰고, 표에 `약`을 붙여 표시합니다.

### 경로 모양

호스는 꺾인 직선이 아니라 곡선으로 계산합니다. 입구, 중간점 C, 출구를 지나는 매끈한 3차 곡선이고, 미지수 수는 늘지 않습니다. `curve`로 고릅니다.

| 값 | 화면 | 뜻 |
| --- | --- | --- |
| `true` (기본) | 곡선, 구멍에 수직 | 호스가 구멍에서 벽에 수직으로 드나듭니다 |
| `"free"` | 곡선, 끝 방향 자유 | 끝 방향을 정하지 않습니다 |
| `false` | 꺾인 직선 | 이전 방식입니다. C에서 꺾입니다 |

평균 경로 오차(cm)입니다. 가상 호스는 복원 모델과 다른 식으로 만들었습니다.

| 호스 모양 | 꺾인 직선 | 끝 자유 곡선 | 구멍 수직 곡선 |
| --- | --- | --- | --- |
| 수직으로 나와 완만히 내려감 | 0.43 | 0.43 | 0.06 |
| 수직, 옆으로 휨 | 1.28 | 1.26 | 0.26 |
| 수직, S자 | 1.30 | 1.42 | 0.97 |
| 비스듬히 나오는 직선 | 0.04 | 0.04 | 0.52 |
| 비스듬히 나오는 휨 | 0.46 | 0.27 | 1.31 |
| 실측 Run #40 | 0.36 | 0.39 | 0.39 |
| 실측 Run #54 | 0.72 | 0.71 | 0.77 |

호스가 구멍에서 비스듬히 빠진다면 구멍 수직 곡선은 오히려 나빠집니다. 이때는 끝 자유 곡선을 쓰고 χ²/N을 비교하세요. 가상 호스 5가지에서는 두 곡선 중 χ²/N이 낮은 쪽이 경로 오차도 작았습니다. 실측 Run #40과 #54에서는 세 방식의 χ²/N과 경로 오차가 거의 같아서 구분되지 않습니다. 중간점이 하나뿐이라 S자처럼 복잡한 모양은 최대 오차가 3 cm 넘게 남습니다.

### 자동 선택의 한계

실측 Run #54는 굵기 변화와 뒤쪽 출구를 맞게 고릅니다. 유량 없이는 점수가 479로 Y자 483과 가까워 경고가 나오고, 뒤쪽 출구 유량을 넣으면 407로 합류 관 479와 벌어집니다. 평균 경로 오차는 0.53 cm, 최대 1.17 cm이고, 굵기 바뀌는 점의 오차는 1.8 cm입니다. 실측 Run #40도 한 줄 관을 맞게 고릅니다.

가상 Run #54(3 mm에서 5 mm로 굵어지는 관)에서도 맞게 고릅니다. 가상 호스가 곡선이면 굵기 바뀌는 점의 오차가 0.02 cm이고, 꺾인 직선이면 0.53 cm입니다.

실측 Run #54는 설계대로 움직이지 않습니다. 농도가 같고 유량이 보존된다면 철 양 비가 2.78이어야 하지만 맞춘 값은 약 27입니다. 실제 경로에 설계값을 고정하면 χ²/N이 약 8로 나빠집니다. 3 mm 구간의 신호가 예상보다 훨씬 약해서, 현재 앞머리 모델이 이 구간을 제대로 설명하지 못합니다. 그래서 앞뒤 속도와 철 양을 따로 맞추고, 신호 크기 비로 낸 내경이 설정의 절반보다 작거나 두 배보다 크면 판정 불가로 둡니다.

앞머리 모델이 설명 못 하는 신호가 있을 때를 보려고 가상 데이터에 Run #40에서 맞추고 남은 신호를 더해 시험했습니다.

| --- | --- | --- | --- |

남은 신호가 크면 구조 선택을 믿기 어려우므로, χ²/N이 2보다 크면 결과에 경고를 표시합니다.

### 구조 키우기

정해 둔 후보(한 줄 관, 굵기 변화, 합류 관, Y자)에 없는 구조도 찾을 수 있게, 한 줄 관 답에서 출발해 부품을 하나씩 더해 봅니다 (`engine/grow.py`).

| 부품 | 하는 일 |
| --- | --- |
| 휘어짐 | 곡선이 지나는 점을 하나 더함 (S자처럼 두 번 휘는 관) |
| 굵기 변화 | 관을 둘로 나누고 뒤쪽의 철 양과 속도를 따로 둠 (3 mm ↔ 5 mm의 단면적 비에서 출발) |
| 갈라졌다 모임 | 관 일부(입구에서부터, 가운데, 출구까지 세 가지)를 두 갈래로 바꿈. 갈래는 앞뒤 또는 위아래로 벌려서 출발 |
| 갈래 휘어짐 | 두 갈래 중 하나에 곡선이 지나는 점을 더함 |

단계마다 모든 부품 후보를 성긴 모델로 맞추고, 출구마다 앞선 3개를 원래 해상도로 다듬습니다. 가장 좋은 후보는 잔차 상관과 크기로 보정한 BIC 꼴의 개선량(χ² 감소 ÷ c − 늘어난 매개변수 수 × ln(N/f))이 10 이상일 때만 남기고, 아니면 멈춥니다. 마지막에는 다른 후보와 같은 [구조 고르기](#구조-고르기) 점수로 비교합니다. 같은 굵기의 구간끼리는 철 양과 속도를 함께 쓰고, 갈라진 두 갈래는 갈래마다 속도만 따로 둡니다.

`auto`에서 `grow: true`로 켜면 구조 키우기 결과도 후보 목록에 들어갑니다. 키운 결과가 후보 구조 하나와 같은 모양(굵기 변화 하나, 합류 하나)이면 그 후보를 여러 시작점에서 맞춘 답을 씁니다. 표준 블라인드 4건(#40, #53, #54, #58)에서는 켜도 고른 구조가 바뀌지 않았고, 계산 시간은 CPU 1개에서 약 10~20초 늘었습니다. 가상 호스(두 번 휘는 S자, 휘는 굵기 변화 관)에서도 χ²/N이 이미 잡음 수준이라 부품이 더해지지 않았습니다. 그래서 기본은 꺼 두고, 후보에 없는 구조를 실험할 때 씁니다.

### ± 범위와 센서 점검

**± 범위**는 고른 답에서 맞춤값을 조금씩 바꿔 잔차가 얼마나 늘어나는지(야코비안)로 구한 공분산에, 구조 고르기의 보정 배율을 곱한 것입니다. 측정 잡음만 따진 값이라 센서 위치 오차 같은 다른 오차는 들어 있지 않습니다. 실제 점을 알면(`truth_points`) 그 점이 ± 범위의 몇 배 밖에 있는지도 보여 줍니다. 3배보다 크면 잡음이 아니라 모델과 장치가 다른 것입니다. #54는 25배, #58은 3배입니다.

**센서 점검**은 철이 오기 전에 잰 코일 자기장 크기 ÷ 비오-사바르 계산값입니다. 이 비는 모든 센서가 같아야 합니다. 코일 자기장 크기는 거의 a 방향으로만 변하므로(앞면 자리에서 1 cm에 약 140 μT), 한 센서만 비가 다르면 그 센서의 a 위치가 틀렸을 가능성이 큽니다. `b0_fix`로 이 차이만큼 a를 옮겨 맞출 수 있습니다. 결과는 기준 비에 민감해서 기본은 꺼 두었습니다([표](#사람이-알려-주지-않은-시험)). 센서 점검에 경고가 나오면 먼저 그 센서의 위치를 다시 재는 것이 좋습니다. 센서는 프로브 끝의 **링 없는 점**(±50 G 소자) 아래를 기준으로 재야 합니다.

### 결과 읽는 법

- **χ²/N**: 1에 가까울수록 잡음 수준까지 맞은 것입니다. 괄호의 철 없음 값보다 많이 작아야 의미가 있습니다. **맞춘 구간** 안에서 계산한 값입니다.
- **센서 위치 경고**: 코일 자기장은 위치마다 크기가 달라서, 측정 크기가 다른 센서 자리와 더 잘 맞으면 두 센서가 바뀐 것 같다고 표시합니다.
- **맞춘 구간**: 앞머리가 상자를 지나는 구간입니다. 그 뒤에는 뒤따르는 철과 호스에 남은 철이 섞여 앞머리 모델로 설명되지 않아서 경로를 맞출 때 쓰지 않습니다. 아래 그래프는 전체 시간을 그리므로 이 구간 뒤에서 측정과 모델이 벌어지는 것은 정상입니다.
- **실제 경로로 맞출 때 χ²/N**: 복원 경로의 값보다 크게 높지 않아야 합니다. 틀린 경로의 χ²/N이 더 낮다면 신호가 부족해 복원을 믿을 수 없다는 뜻입니다. 실제 경로는 적힌 점을 잇는 매끈한 곡선으로 쓰며, 두 점이면 직선입니다.
- **다른 후보**: 가는 반투명 관으로 그려집니다. 후보끼리 많이 다른 곳이 불확실한 곳입니다.
- **주황 안개**: 분기점, 합류점, 굵기 바뀌는 점의 ± 범위(1σ)입니다. 초록 공은 `truth_points`로 적은 실제 점입니다.
- **구조 키우기 줄**: 단계마다 더한 부품과 보정 개선량입니다.
- **아래 그래프**: 옅은 선이 측정, 진한 선이 모델입니다. 겹칠수록 잘 맞은 것입니다.

## 호스 내경 추정

자기장 측정만으로는 내경을 직접 알 수 없습니다. 호스가 센서에서 호스 굵기보다 훨씬 멀어서 철이 만드는 신호는 $\lambda = \chi_\mathrm{eff} A$, 즉 실효 자화율과 단면적의 곱으로만 나타나기 때문입니다. 그래서 Capstone 측정값으로 앞머리 속도 $U$를 구하고, 출구에서 잰 유량 $Q$를 더해 계산합니다.

$$d = 2\sqrt{\frac{Q}{\pi U}}$$

복원에서 고른 구조의 경로를 고정하고 구간마다 속도를 구합니다. 설정에 실제 경로가 있고 측정을 복원 경로만큼 맞추면 실제 경로를 쓰고, $\chi^2/N$이 복원 경로의 1.25배를 넘으면 복원 경로를 씁니다. `step`은 굵기가 바뀌기 전과 뒤, `y`와 `loop`는 입구 쪽과 갈래별 구간입니다. `loop`의 갈래는 갈래별 유량을 재기 어려워 신호 크기 비로만 내경을 냅니다.

속도는 첫 앞머리가 상자를 지나는 구간만 맞춰서 구합니다. 그 뒤의 신호에는 뒤따르는 덩어리와 호스에 남은 철이 섞여 있어, 전체 구간을 맞추면 Run #40의 속도가 실제의 절반 아래로 나옵니다.

속도를 바꿔 가며 맞춤이 얼마나 나빠지는지 보고, $U/2$와 $2U$ 양쪽에서 3σ 넘게 나빠지지 않거나 속도 불확도가 50%를 넘으면 **판정 불가**로 표시하고 값을 내지 않습니다. 불확도에는 맞춤 오차, 구간 길이를 바꿨을 때의 차이, 유량 오차 5%를 넣습니다.

구간이 나뉘는 호스에서 신호가 충분히 크면 농도가 같다는 가정으로 $d_k = d_\mathrm{입구} \sqrt{\lambda_k / \lambda_\mathrm{입구}}$ 도 함께 보여 줍니다. 이 값은 유량이 필요 없습니다.

Run #40의 검증은 잠정입니다. 유량 0.21 mL/s는 실험 기록의 값이고, 모은 양 ÷ 시간으로 직접 잰 값인지 아직 확인하지 못했습니다. 3 mm 단면적으로 계산한 값이라면 정답이 입력에 들어간 것이므로 검증이 되지 않습니다. Run #49의 출구별 유량도 기록된 모은 양 비율(12:4)로 총유량 0.21 mL/s를 나눈 값입니다.

앞머리 배율 $\gamma$($U = \gamma Q / A$)는 1로 두었습니다. 실제 값이 다르면 내경은 $\sqrt{\gamma}$배 달라지므로 곧은 호스 흐름 보정으로 따로 재야 합니다. 값까지 비교할 수 있는 실측은 Run #40 한 건뿐이어서, 다른 내경의 실측으로 더 확인해야 합니다.

Run #40에서 센서를 하나씩 빼면 S1은 2.91 mm, S2와 S3은 3.15 mm, 출구 쪽 S4는 3.80 mm가 나옵니다. 앞머리가 통과하는 시간을 재려면 출구 가까이에 센서가 꼭 있어야 합니다. 표시되는 불확도에는 이 센서 배치 영향이 들어 있지 않습니다.

## 작동 방식

```
index.html, assets/   화면
assets/table.js       CSV에서 필요한 열만 읽기
assets/worker.js      Pyodide(웹어셈블리 파이썬)로 계산을 돌리는 워커
engine/recon3d.py     복원 프로그램
engine/grow.py        구조 키우기 (후보 없이 부품을 더해 가며 구조 찾기)
engine/thickness.py   호스 내경 추정
engine/template.html  결과 3D 화면
configs/              Run별 설정
```

웹 버전이 계산을 다시 구현한 것이 아니라 `engine/`의 파이썬 프로그램을 브라우저에서 그대로 실행합니다. 그래서 프로그램을 고칠 때도 이 파일들만 고치면 됩니다.

맞춤은 앞머리가 상자를 지나는 구간만 씁니다. 신호가 뚜렷해지는 시각을 잡고 곧은 경로로 속도를 대략 구해서 구간을 정합니다. 평균 경로 오차는 실측 Run #40에서 분석 구간 전체로 맞추면 0.58 cm, 이 구간으로 맞추면 0.39 cm입니다. 실측 Run #54에서는 2.21 cm와 0.77 cm입니다.

맞춤은 세 단계입니다.

1. 호스와 시간을 성기게 자른 모델로 시작점마다 8걸음만 맞춥니다. 시작점은 6개, 갈래가 있는 구조는 12개입니다 (`starts`, `nfev1`).
2. 후보마다 잘 맞은 3개를 같은 모델로 수렴시킵니다 (`keep`, `nfev2`).
3. 앞선 후보의 답 2개를 원래 해상도로 마무리합니다 (`near`, `polish`, `nfev3`).

계산 조각은 입력과 출력이 숫자뿐이라 워커 수와 상관없이 답이 같습니다.

호스를 일정한 간격의 점으로 나눌 때 점 수는 정수입니다. 예전에는 점 하나의 호스 길이를 설정값으로 고정해서, 경로 길이가 바뀌어 점 수가 하나 늘 때마다 전체 신호가 약 2.4% 튀었습니다. 이제는 점 하나의 길이를 실제 간격으로 계산합니다. 굵기 바뀌는 점 P도 걸친 조각에서 앞뒤 값을 나눠 갖습니다. 그래서 목표 함수가 매끈해져서 시작점이 적어도 같은 답에 도달합니다.

Pyodide는 jsDelivr에서 불러오므로 학교 망에서 `cdn.jsdelivr.net`이 막혀 있으면 계산이 시작되지 않습니다. 버전은 `assets/worker.js` 맨 위에 고정되어 있습니다.
