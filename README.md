# 통로 3D 복원

불투명한 상자 속 호스에 철 현탁액을 흘리고, 바깥 자기장 센서 4대의 측정값으로 호스가 지나간 길을 3차원으로 복원하고 호스 내경을 추정하는 웹 프로그램입니다.

설치할 것이 없습니다. 페이지를 열고 Capstone CSV를 넣으면 브라우저 안에서 계산하고, 돌려 볼 수 있는 3D 결과를 보여 줍니다. 측정 파일은 서버로 전송되지 않습니다.

페이지 주소: <https://hwisu0.github.io/recon3d/>

## 사용법

1. **측정 파일**: Capstone에서 File > Export Data > Export to file로 저장한 CSV를 넣습니다. 여러 Run이 든 파일도 됩니다.
2. **실험 조건**: 기존 설정을 고르거나 설정 JSON을 연 뒤 이번 Run에 맞게 고칩니다. 내경까지 구하려면 출구별 유량도 넣습니다.
3. **복원 시작**을 누릅니다. 끝나면 3D 결과가 오른쪽에 나타나고, HTML과 JSON으로 저장할 수 있습니다.

복원한 결과는 자동으로 **결과** 탭에 쌓이고, 누르면 다시 볼 수 있습니다. 결과는 쓰고 있는 브라우저 안에만 저장되어 다른 컴퓨터나 팀원에게는 보이지 않고, 브라우저 데이터를 지우면 사라집니다. 다른 컴퓨터로 옮길 때는 **HTML 저장**으로 받은 파일을 그쪽에서 **결과 HTML 가져오기**로 넣습니다.

처음 실행할 때는 파이썬 실행 환경 약 40 MB를 내려받습니다. 다음부터는 브라우저에 저장된 것을 씁니다. 구조 후보를 하나만 맞출 때 Run #40은 약 30초, Run #49는 약 1분 20초 걸렸습니다. 구조와 출구를 자동으로 고르면 후보 수만큼 길어져서, 후보 6개인 Run #54 설정은 약 4분 걸렸습니다. 컴퓨터 성능에 따라서도 달라집니다.

### 자주 바꾸는 설정

| 화면 항목 | JSON 키 | 뜻 |
| --- | --- | --- |
| Run 번호 | `run` | CSV 안의 Run 번호 |
| 기준 구간 | `baseline` | 철이 들어오기 전, 아무도 건드리지 않은 구간 [시작, 끝] 초 |
| 분석 구간 | `t_window` | 분석할 구간 [시작, 끝] 초. 흔들린 구간은 뺍니다 |
| 뺄 구간 | `mask` | 센서별로 뺄 구간. 예: `{"S2": [[69, 999]]}` |
| 철 도착 예상 시각 | `t_front_guess` | 철이 상자에 올 것 같은 시각. 대략이면 되고 비워도 됩니다 |
| 센서 위치 | `sensors` | (a, b, c) cm. 정확할수록 좋습니다 |
| 구조 | `topology` | `auto`, `single`, `step`, `loop`, `y` |
| 출구 | `exit` | `auto` 또는 출구 번호(0부터). 안 쓴 출구가 있으면 `auto`로 고릅니다 |
| 호스 내경 | `hose_mm` | `{"stem": 3, "branches": [5]}`. `branches`는 `step`이면 바뀐 뒤 굵기, `loop`와 `y`면 갈래별 굵기 |
| 입구 앞 호스 | `upstream_len` | 주사기~입구 길이 (cm) |
| 유량 | `flow_mL_s` | 출구마다 모은 양 ÷ 걸린 시간 (mL/s). 예: `[0.1575, 0.0525]` |
| 실제 경로와 비교 | `truth`, `truth_points` | 실제 경로나 일부 점을 알 때만 씁니다. 블라인드 시험이면 끕니다 |

### 구조 고르기

`topology`가 `auto`면 후보 구조를 모두 맞춰 보고 BIC가 가장 작은 것을 고릅니다. 결과의 **구조** 칸에서 후보별 점수를 비교할 수 있습니다.

| 값 | 구조 |
| --- | --- |
| `single` | 한 줄 관. 중간점 1개, 굵기 일정 |
| `step` | 중간에 굵기가 바뀌는 한 줄 관. 바뀌는 점 P와 앞뒤 굵기 비를 찾습니다 |
| `loop` | 갈라졌다 다시 모이는 관. 분기점 J1, 합류점 J2, 갈래마다 중간점을 찾습니다 |
| `y` | 갈래마다 다른 출구로 나가는 Y자 |

`candidates`로 후보를 줄일 수 있고, `exit`가 `auto`면 출구마다 모든 후보를 맞춥니다. `try_y`는 Y자를 후보에 넣을지 정합니다. `prior`의 `straight_sigma_cm`은 곧은 관을, `downhill`은 내리막 관을 선호하게 합니다. 후보가 많을수록 오래 걸리므로 구조나 출구를 알면 직접 정하는 편이 빠릅니다.

### 경로 모양

호스는 꺾인 직선이 아니라 곡선으로 계산합니다. 입구, 중간점 C, 출구를 지나는 매끈한 3차 곡선이고, 미지수 수는 늘지 않습니다. `curve`로 고릅니다.

| 값 | 화면 | 뜻 |
| --- | --- | --- |
| `true` (기본) | 곡선, 구멍에 수직 | 호스가 구멍에서 벽에 수직으로 드나듭니다 |
| `"free"` | 곡선, 끝 방향 자유 | 끝 방향을 정하지 않습니다 |
| `false` | 꺾인 직선 | 이전 방식입니다. C에서 꺾입니다 |

평균 경로 오차(cm)입니다. 가상 호스는 복원 모델과 다른 식으로 만들었습니다.

| 호스 모양 | 꺾인 직선 | 끝 자유 곡선 | 구멍 수직 곡선 |
| --- | --- | --- | --- |
| 수직으로 나와 완만히 내려감 | 0.70 | 0.43 | 0.07 |
| 수직, 옆으로 휨 | 1.40 | 1.47 | 0.18 |
| 수직, S자 | 1.41 | 1.36 | 0.96 |
| 비스듬히 나오는 직선 | 0.05 | 0.05 | 0.52 |
| 비스듬히 나오는 휨 | 0.44 | 0.22 | 1.28 |
| 실측 Run #40 | 0.96 | 0.55 | 0.49 |

호스가 구멍에서 비스듬히 빠진다면 구멍 수직 곡선은 오히려 나빠집니다. 이때는 끝 자유 곡선을 쓰고 χ²/N을 비교하세요. 시험한 6가지에서는 두 곡선 중 χ²/N이 낮은 쪽이 경로 오차도 작았습니다. 중간점이 하나뿐이라 S자처럼 복잡한 모양은 최대 오차가 3 cm 넘게 남습니다.

### 자동 선택의 한계

가상 Run #54(3 mm에서 5 mm로 굵어지는 관)에서는 후보 6개 중 굵기 변화와 뒤쪽 출구를 맞게 골랐습니다. 가상 호스가 곡선이면 굵기 바뀌는 점의 오차가 0.03 cm이고, 꺾인 직선이면 구조는 맞게 고르지만 오차가 0.62 cm로 커집니다. 하지만 실제 곧은 호스인 Run #40에서는 `prior`를 넣어도 합류 관을 고릅니다(BIC 7655, 한 줄 관 8471). 실측에는 앞머리 모델로 설명되지 않는 신호가 많아 매개변수가 많은 구조가 유리해지는 것으로 보입니다. 그래서 고른 구조의 χ²/N이 2보다 크면 결과에 경고를 표시합니다. Run #40 기본 설정은 한 줄 관으로 고정했습니다.

좌표 (a, b, c)는 a가 입구면에서 출구 쪽, b가 앞면(S3 쪽)에서 안쪽, c가 탁자에서 높이입니다. 그 밖의 항목은 화면의 **JSON** 에서 고칩니다. 새 설정을 목록에 넣으려면 파일을 `configs/`에 두고 `configs/index.json`에 한 줄 추가합니다.

### 결과 읽는 법

- **χ²/N**: 1에 가까울수록 잡음 수준까지 맞은 것입니다. "철 없다고 볼 때" 값보다 많이 작아야 의미가 있습니다.
- **실제 경로로 맞출 때 χ²/N**: 복원 경로의 값보다 크게 높지 않아야 합니다. 틀린 경로의 χ²/N이 더 낮다면 신호가 부족해 복원을 믿을 수 없다는 뜻입니다. 실제 경로는 곡선으로 바꾸지 않고 적힌 그대로 씁니다.
- **다른 후보**: 가는 반투명 관으로 그려집니다. 후보끼리 많이 다른 곳이 불확실한 곳입니다.
- **아래 그래프**: 옅은 선이 측정, 진한 선이 모델입니다. 겹칠수록 잘 맞은 것입니다.

## 호스 내경 추정

자기장 측정만으로는 내경을 직접 알 수 없습니다. 호스가 센서에서 호스 굵기보다 훨씬 멀어서 철이 만드는 신호는 $\lambda = \chi_\mathrm{eff} A$, 즉 실효 자화율과 단면적의 곱으로만 나타나기 때문입니다. 그래서 Capstone 측정값으로 앞머리 속도 $U$를 구하고, 출구에서 잰 유량 $Q$를 더해 계산합니다.

$$d = 2\sqrt{\frac{Q}{\pi U}}$$

복원에서 고른 구조의 경로를 고정하고 구간마다 속도를 구합니다. `step`은 굵기가 바뀌기 전과 뒤, `y`와 `loop`는 입구 쪽과 갈래별 구간입니다. `loop`의 갈래는 갈래별 유량을 재기 어려워 신호 크기 비로만 내경을 냅니다.

속도는 첫 앞머리가 상자를 지나는 구간만 맞춰서 구합니다. 그 뒤의 신호에는 뒤따르는 덩어리와 호스에 남은 철이 섞여 있어, 전체 구간을 맞추면 Run #40의 속도가 실제의 절반 아래로 나옵니다.

속도를 바꿔 가며 맞춤이 얼마나 나빠지는지 보고, $U/2$와 $2U$ 양쪽에서 3σ 넘게 나빠지지 않으면 **판정 불가**로 표시하고 값을 내지 않습니다. 불확도에는 맞춤 오차, 구간 길이를 바꿨을 때의 차이, 유량 오차 5%를 넣습니다.

구간이 나뉘는 호스에서 신호가 충분히 크면 농도가 같다는 가정으로 $d_k = d_\mathrm{입구} \sqrt{\lambda_k / \lambda_\mathrm{입구}}$ 도 함께 보여 줍니다. 이 값은 유량이 필요 없습니다.

곧은 호스와 Y자, 곡선 호스의 가상 데이터는 모델 자체로 만들고 측정과 같은 크기의 잡음을 넣은 것입니다. 실제 호스처럼 뒤따르는 덩어리가 없어 실측보다 쉬운 시험입니다. 꺾인 굵기 변화 관은 곡선 모델과 다른 모양을 곡선 모델로 맞춘 경우로, 경로 모양이 틀리면 굵기 바뀌기 전 내경과 신호 크기 비가 표시된 불확도를 넘어 틀릴 수 있음을 보여 줍니다.

Run #40의 검증은 잠정입니다. 유량 0.21 mL/s는 실험 기록의 값이고, 모은 양 ÷ 시간으로 직접 잰 값인지 아직 확인하지 못했습니다. 3 mm 단면적으로 계산한 값이라면 정답이 입력에 들어간 것이므로 검증이 되지 않습니다. Run #49의 출구별 유량도 기록된 모은 양 비율(12:4)로 총유량 0.21 mL/s를 나눈 값입니다.

앞머리 배율 $\gamma$($U = \gamma Q / A$)는 1로 두었습니다. 실제 값이 다르면 내경은 $\sqrt{\gamma}$배 달라지므로 곧은 호스 흐름 보정으로 따로 재야 합니다. 값까지 비교할 수 있는 실측은 Run #40 한 건뿐이어서, 다른 내경의 실측으로 더 확인해야 합니다.

Run #40에서 센서를 하나씩 빼면 S1은 2.92 mm, S2와 S3은 3.16 mm, 출구 쪽 S4는 3.80 mm가 나옵니다. 앞머리가 통과하는 시간을 재려면 출구 가까이에 센서가 꼭 있어야 합니다. 표시되는 불확도에는 이 센서 배치 영향이 들어 있지 않습니다.

## 작동 방식

```
index.html, assets/   화면
assets/worker.js      Pyodide(웹어셈블리 파이썬)로 계산을 돌리는 워커
engine/recon3d.py     복원 프로그램
engine/thickness.py   호스 내경 추정
engine/template.html  결과 3D 화면
configs/              Run별 설정
```

웹 버전이 계산을 다시 구현한 것이 아니라 `engine/`의 파이썬 프로그램을 브라우저에서 그대로 실행합니다. 그래서 프로그램을 고칠 때도 이 파일들만 고치면 됩니다.

Pyodide는 jsDelivr에서 불러오므로 학교 망에서 `cdn.jsdelivr.net`이 막혀 있으면 계산이 시작되지 않습니다. 버전은 `assets/worker.js` 맨 위에 고정되어 있습니다.

## 내 컴퓨터에서 실행하기

웹 대신 일반 파이썬으로도 돌릴 수 있습니다.

```
python -m pip install numpy pandas scipy
python engine/recon3d.py configs/config_r49.json
```

CSV는 설정의 `csv` 경로에 두고, 결과는 `out` 경로에 `.json`과 `.html`로 저장됩니다.
